## Parallel Codex worktrees

- Preserve one task, task branch, linked worktree, active owner, and task-scoped
  Engram project as one invariant. Do not reuse any member of that tuple for a
  concurrent writer.
- Authority is ordered: live Git plus the prepared descriptor and owner claim
  control writes; task-qualified ctx provides provenance; Engram provides
  curated memory. Provenance and memory never establish current ownership.
- Optional Engram plugin hooks do not honor the task-project process override
  and must be absent under the named `parallel-work` profile. A provider-backed
  canary behaviorally proved hook suppression, but it did not qualify the
  foundation because task-project MCP resolution and reviewer creation failed.
- An outer `ENGRAM_PROJECT` is necessary for worker/helper checks but does not
  configure Codex-managed MCP children. Launch and resume must also pass the
  descriptor task project through
  `mcp_servers.engram.env.ENGRAM_PROJECT`; `mem_current_project` remains the
  fail-closed runtime check. A disposable `ENGRAM_DATA_DIR` is allowed only as
  an existing strict child of that task worktree.
- The owner claim uses Codex's runtime thread ID, not a coordinator-selected
  launch label. For a default full-history reviewer fork, omit `agent_type`;
  record spawn attempts separately from successfully created reviewers and do
  not constrain observed canary values to expected values.
- The tested sources are
  `codex-config/.codex/skills/orchestrating-parallel-worktrees/SKILL.md` and
  `codex-config/.codex/skills/orchestrating-parallel-worktrees/scripts/worktree-session`.
- The helper's owner claim is a cooperative protocol, not an operating-system
  ACL. Other tools can still write, so coordinators and workers must obey the
  claim and explicit handoff/release boundary.
- After compaction or resume, re-run claim and task-project verification and
  reconcile the descriptor against current Git before another write.
- Build generated verification wrappers for their declared interpreter. In
  zsh, `status` is read-only and `path` is tied to `PATH`; use descriptive
  variables such as `git_status_text` and `changed_paths_text`, and invoke Bash
  explicitly for Bash-specific multiline wrappers. A thin parallel pilot
  reproduced the `status` collision in two independent writers.
- The task-project launch remediation passed deterministic review, was
  integrated locally as `d423441`, and became live through the existing Stow
  link on 2026-08-09. A fresh qualifying provider canary remains pending;
  provider-free MCP configuration evidence is not provider-behavior proof.
- Creating a Stow link is a separate activation action. Once an installed file
  already links to tracked source, editing or integrating that source updates
  the live installed file immediately. Before defining approval gates, inspect
  the target with `readlink` or `realpath` and compare source and live hashes;
  combine integration and effective activation approval or stage outside the
  live link. Provider canaries, remote pushes, and cleanup remain separate.
- See the approved design at
  `docs/superpowers/specs/2026-08-08-parallel-codex-worktree-orchestration-design.md`;
  do not copy mutable session, claim, or dirty-worktree state into this file.

## Neovim and LazyVim

- `nvim/.config/nvim/lazyvim.json` is the source of truth for LazyVim extras.
  Do not duplicate those imports in `lua/config/lazy.lua`.
- Keep lazy.nvim's global `defaults.version` set to `false`. Neovim plugins do
  not all publish compatibility fixes as tagged releases; globally preferring
  tags selected Trouble 3.7.1 after Neovim 0.12 removed the Treesitter
  highlighter `_on_line` callback. Trouble's compatible implementation moved to
  `_on_range` on its main branch.
- Prefer LazyVim extra defaults over full local plugin configurations. Add only
  narrowly scoped options or keymaps so upstream fixes and integrations remain
  effective.
- Assign static `FZF_DEFAULT_OPTS` deterministically. Appending to an inherited
  value makes every nested interactive shell duplicate the same options.
- Snacks is the notification surface. A repeated notification may originate in
  another plugin's redraw or decoration provider; inspect the namespace and
  traceback before changing notifier settings.
- Current nvim-treesitter parsers belong under
  `~/.local/share/nvim/site/parser`. Legacy untracked `parser/` or
  `parser-info/` directories inside the plugin checkout can dirty the checkout
  and obstruct updates. Current nvim-treesitter maps the `jsonc` filetype to
  the `json` parser; an older standalone `jsonc.so` is not updateable by
  `TSUpdate` and should be removed only through an explicit cleanup gate.
- Install stable Neovim through Homebrew. Do not retain a parallel `HEAD` keg:
  it can remain linked to an older tree-sitter shared-library ABI after formula
  upgrades.
